# DVF Explorer Helm chart

A chart supporting read-only published Parquet datasets and the legacy single-writer FastAPI + DuckDB architecture. Requires Kubernetes 1.27+ and Helm 3 or 4. Includes a Deployment, Service, optional Ingress, persistent volume claim, ServiceAccount, and `helm test` health pod.

## Install

For legacy local mode, create the `dvf-admin` Secret in the target namespace using your secret manager, with a nonempty random `token` key. Published mode does not reference this Secret. The chart never renders credentials. Ensure the image has been published by CI before installing. For SSPCloud, copy `charts/values-sspcloud.yaml` outside the repository, replace the example hostname, IngressClass, TLS secret and StorageClass, then use that copy below.

```sh
helm upgrade --install dvf ./charts \
  --namespace dvf --create-namespace \
  -f /path/to/values-sspcloud.yaml \
  --set image.tag=sha-REPLACE_WITH_FULL_COMMIT_SHA \
  --wait --timeout 10m
helm test dvf --namespace dvf
kubectl --namespace dvf port-forward service/dvf-dvf-explorer 8000:8000
```

`image.digest=sha256:...` takes precedence over tags. The source chart defaults to the moving `main` tag; CI chart packages default to the exact commit image through `Chart.appVersion`. Prefer a SHA tag or digest for repeatable upgrades. The chart artifact is generated by checks before image publication; wait for the **publish** job to succeed before deploying its package.

For legacy local mode, omit `-f`. The chart does not create DNS records or certificates, or assume a particular SSPCloud cluster configuration.

## Persistence and migration

With `dataset.url` empty, exactly one API replica and `Recreate` rollouts prevent competing DuckDB writers. Multiple replicas require a published dataset and `persistence.enabled=false`; no HPA is generated. Manual legacy imports run in the API process. The chart does not create a CronJob.

The default claim requests 100 GiB and is retained on Helm uninstall with `helm.sh/resource-policy: keep`. Retained claims remain operator-managed and can be reused through `persistence.existingClaim`. This is not a backup: keep independent consistent snapshots and archive copies. In legacy local mode, `persistence.enabled=false` is for disposable testing only; database and campaign state then disappear with the pod. In published mode, S3 retains the dataset but local caches and BAN indexes are rebuilt after pod replacement.

When migrating an existing installation, stop any previous sync CronJob and API Deployment before reusing its data claim. Set `persistence.existingClaim=dvf-data` to reuse the former PVC. Never run competing DuckDB writers against that claim. Check volume ownership: the chart uses UID/GID 10001 and fsGroup 10001. Keep a consistent backup before migrating resource ownership.

## Dataset updates

The web application reads an already published DVF+ dataset from S3. No scheduled import runs during visits. Prepare and publish newer DVF+ releases separately using [the worker guide](../docs/s3-parquet.md). BAN indexes are prepared per department and retained on the data volume; their refresh is explicit, as described in [the address guide](../docs/addresses.md).

Upgrading this chart removes the former Helm-managed sync CronJob. Already running Jobs are separate resources: finish or stop any old import before changing its data volume or deployment. External schedules are not managed by this chart.

For a manual sync in legacy local mode:

```sh
kubectl --namespace dvf exec deployment/dvf-dvf-explorer -- \
  env DVF_API_URL=http://127.0.0.1:8000 python backend/sync_remote.py
```

## Configuration

| Values | Purpose |
| --- | --- |
| `dataset.url`, `dataset.endpoint`, `dataset.anonymous` | Published Parquet dataset and S3 access mode |
| `image.repository`, `image.tag`, `image.digest` | Published application image |
| `imagePullSecrets` | Existing registry Secrets if Docker Hub image is private |
| `admin.existingSecret`, `admin.tokenKey` | Existing administration token Secret |
| `ingress.*` | Domain, IngressClass, annotations and TLS references |
| `persistence.*` | Claim, capacity, StorageClass and retention annotation |
| `duckdb.memoryLimit`, `duckdb.threads` | Database query resource budget |
| `resources` | API resource requests/limits |
| `extraEnv`, `extraEnvFrom` | Optional API runtime environment / Secret references |
| `nodeSelector`, `affinity`, `tolerations` | API placement |

Keep environment overrides outside Git and do not override `DVF_ADMIN_TOKEN`, `DVF_DATASET_URL` or `DVF_DATA_DIR` through `extraEnv`. Set `dataset.url` to the published `current.json` URL/URI. Public SSPCloud values use anonymous S3 reads, one replica, a 20 GiB persistent volume for BAN indexes and caches, and Recreate rollouts to avoid overlapping mounts. Published deployments with disposable caches can use multiple replicas and `persistence.enabled=false`, which enables rolling updates. The administration Secret reference is omitted in published mode. Readiness checks publication availability; liveness does not depend on S3.

For a private bucket, set `dataset.anonymous=false` and provide renewable AWS credentials through `extraEnvFrom` referencing a separately managed Secret. The DVF+ publication worker runs separately; see [the worker guide](../docs/s3-parquet.md).

Changing image tags triggers a rollout; repushing the moving `main` tag does not change the Deployment specification. Use a new SHA tag on each upgrade. `helm rollback` rolls back application resources, not data or database migrations. Verify data compatibility and take a consistent backup before upgrades that alter storage formats.

## Validation and packaging

```sh
helm lint charts --strict
.venv/bin/python scripts/check_chart.py
helm package charts --destination dist/charts
```

CI validates default, SSPCloud, existing-claim, ephemeral and digest configurations. Chart archives are available as GitHub Actions artifacts; there is no Helm registry or automatic cluster deployment configured. Bump `Chart.yaml` version when releasing chart changes.
