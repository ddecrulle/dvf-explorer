# DVF Explorer Helm chart

A `helm create`-based chart for the current single-writer FastAPI + DuckDB architecture. Requires Kubernetes 1.27+ and Helm 3 or 4. Includes a Deployment, Service, optional Ingress, persistent volume claim, ServiceAccount, seasonal HTTP CronJob and `helm test` health pod.

## Install

Create the `dvf-admin` Secret in the target namespace using your secret manager, with a nonempty random `token` key. The chart references this existing Secret and never renders credentials. Ensure the image has been published by CI before installing.

```sh
helm upgrade --install dvf ./charts/dvf-explorer \
  --namespace dvf --create-namespace \
  --set image.tag=sha-REPLACE_WITH_FULL_COMMIT_SHA \
  --wait --timeout 10m
helm test dvf --namespace dvf
kubectl --namespace dvf port-forward service/dvf-dvf-explorer 8000:8000
```

`image.digest=sha256:...` takes precedence over tags. The source chart defaults to the moving `main` tag; CI chart packages default to the exact commit image through `Chart.appVersion`. Prefer a SHA tag or digest for repeatable upgrades. The chart artifact is generated by checks before image publication; wait for the **publish** job to succeed before deploying its package.

For SSPCloud, copy `values-sspcloud.yaml` outside the repository and replace the example hostname, IngressClass, TLS secret and StorageClass as appropriate. Pass the copy with `-f`. The chart does not create DNS records or certificates, or assume a particular SSPCloud cluster configuration.

## Persistence and migration

Exactly one API replica and `Recreate` rollouts prevent competing DuckDB writers. The values schema rejects `replicaCount > 1`; no HPA is generated. Imports run in the API process; the CronJob only makes authenticated HTTP calls and never mounts the database volume.

The default claim requests 100 GiB and is retained on Helm uninstall with `helm.sh/resource-policy: keep`. Retained claims remain operator-managed and can be reused through `persistence.existingClaim`. This is not a backup: keep independent consistent snapshots and archive copies. `persistence.enabled=false` is for disposable testing only; database and campaign state then disappear with the pod.

If migrating from `deploy/kubernetes/`, first stop the old CronJob and Deployment, preserve the `dvf-data` PVC, and set `persistence.existingClaim=dvf-data` before installing this chart. Never run old and new API writers against that claim simultaneously. Check volume ownership: the chart uses UID/GID 10001 and fsGroup 10001; the storage driver must support the required permissions. Do not install Helm on top of existing resource names without a deliberate ownership migration.

## Scheduled checks

At 09:00 and 16:00 Europe/Paris on weekdays, the CronJob checks the active April/October campaign through the API. Checks continue until a new publication is fully imported and parcel matching succeeds. Completed campaign state lives on the persistent volume; subsequent jobs skip source polling until the next campaign. Public holidays are included. `sync.enabled=false` removes the CronJob; `sync.suspend=true` pauses scheduling.

For a manual sync outside campaign gating:

```sh
kubectl --namespace dvf exec deployment/dvf-dvf-explorer -- \
  env DVF_API_URL=http://127.0.0.1:8000 python backend/sync_remote.py
```

## Configuration

| Values | Purpose |
| --- | --- |
| `image.repository`, `image.tag`, `image.digest` | Published application image |
| `imagePullSecrets` | Existing registry Secrets if Docker Hub image is private |
| `admin.existingSecret`, `admin.tokenKey` | Existing administration token Secret |
| `ingress.*` | Domain, IngressClass, annotations and TLS references |
| `persistence.*` | Claim, capacity, StorageClass and retention annotation |
| `duckdb.memoryLimit`, `duckdb.threads` | Database query resource budget |
| `resources`, `sync.resources` | API and CronJob resource requests/limits |
| `extraEnv`, `extraEnvFrom` | Optional API runtime environment / Secret references |
| `nodeSelector`, `affinity`, `tolerations` | API placement; nodeSelector/tolerations also apply to sync |

Keep environment overrides outside Git and do not override `DVF_ADMIN_TOKEN` or `DVF_DATA_DIR` through `extraEnv`. S3/Parquet serving is not implemented yet: injecting AWS credentials does not activate it. Future integration can consume Secrets through `extraEnvFrom`; the current application uses the PVC.

Changing image tags triggers a rollout; repushing the moving `main` tag does not change the Deployment specification. Use a new SHA tag on each upgrade. `helm rollback` rolls back application resources, not data or database migrations. Verify data compatibility and take a consistent backup before upgrades that alter storage formats.

## Validation and packaging

```sh
helm lint charts/dvf-explorer --strict
.venv/bin/python scripts/check_chart.py
helm package charts/dvf-explorer --destination dist/charts
```

CI validates default, SSPCloud, existing-claim, ephemeral and digest configurations. Chart archives are available as GitHub Actions artifacts; there is no Helm registry or automatic cluster deployment configured. Bump `Chart.yaml` version when releasing chart changes.
